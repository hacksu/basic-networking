Before attendees arrive

  • Confirm model, console access, three lab ports in one VLAN, two Ethernet hosts, adapters, and cables.
  • Use an isolated network. Record existing settings. A: 192.168.50.10/24; B: 192.168.50.20/24. No wired gateway or DNS.
  • Check subnet conflicts, link forwarding, and narrowly scoped ICMP permissions. Do not disable firewalls globally.
  • Rehearse both hosts and save actual output privately as backup. Hardware commands are examples until verified.
  • Keep exactly one inter-switch cable. Confirm the GL.iNet model, router mode, LAN subnet, and local DHCP. Keep this network separate from the wired lab.
  • If behind schedule, shorten the access overview and skip demo 2. Preserve questions. Give failures at most 60 seconds.
Slide 100:00-01:00

Basic Networking

  • Welcome both beginners and people who have configured networks. Ask who has used ping and who has used a switch console.
  • The aim is to explain an actual path using the equipment on the table. There is no subnet arithmetic quiz.
Slide 201:00-02:00

Start with the equipment

  • Show the TP-Link 5-port Gigabit desktop switch, GL.iNet AC1200 wireless travel router, and Catalyst 3560. The Catalyst has 48 copper 10/100 Fast Ethernet PoE ports and four SFP slots. No SFP modules are available. PoE supplies compatible endpoints; no powered endpoint is confirmed.
  • Two hosts and any Ethernet adapters must be confirmed. All Catalyst demo connections use copper Fast Ethernet ports. Check negotiated speed and duplex during rehearsal. AC1200 alone does not identify the GL.iNet model.
Slide 302:00-04:00

Hub, switch, router

  • There is no physical hub in this inventory. Describe the shared-medium behavior rather than claim to show it.
  • Switches also flood broadcasts and unknown unicasts within the VLAN. Avoid saying they always send to exactly one port.
  • The 3560 is a multilayer switch family; routing depends on software/features and configuration. Keep it in a switching role for this demo. The GL.iNet provides the router, access point, DHCP, NAT, and firewall example in router mode.
Slide 404:00-05:00

Networking vendors

  • Spend one minute recognizing names, not ranking brands. Cisco Catalyst is on the table; UniFi is Ubiquiti’s networking family; HPE Aruba Networking offers campus and branch wired/wireless products.
  • TP-Link makes both desktop switches and Omada business products. Do not imply our unmanaged switch is an Omada device. GL.iNet connects the vendor discussion to the travel router on the table.
  • Shared Ethernet and IP protocols let compatible equipment interoperate. Management, feature support, licensing, and support vary by model and family. A vendor name alone does not determine capabilities.
  • Vendor names link to primary sources. Keep purchasing questions for discussion afterward. The opening device explanation now takes two minutes to preserve the one-hour schedule.
Slide 505:00-09:00

OSI: where would you look?

  • Start at the bottom with a cable, then move upward. Do not ask the audience to memorize all seven names.
  • Contrast an unplugged cable, a missing route, and an HTTP error. Similar symptoms at the browser can have different causes.
Slide 609:00-11:00

TCP/IP uses fewer layers

  • This is the four-layer teaching model. Some materials split the link layer into physical and data link.
  • The mapping is approximate. Keep attention on what each layer does.
Slide 711:00-13:00

Data travels inside other data

  • Trace an HTTP-over-TCP example downward into a signal and upward on the receiver. This is one example, not all web traffic.
  • In ordinary routing the destination IP stays the same while Ethernet addresses change by hop. TTL or hop limit changes too; NAT can rewrite IP addresses and ports.
Slide 813:00-16:00

Three different addresses

  • A MAC address can be assigned or randomized. It is not permanent identity or strong authentication.
  • A host can have multiple interfaces and IP addresses. TCP and UDP have separate port spaces.
Slide 916:00-19:00

Is the destination local?

  • These hosts share 192.168.50.0/24. The mask is 255.255.255.0. Explain the network portion without doing binary exercises.
  • For this Ethernet example, a host sends directly to an on-link peer. For remote traffic, it normally sends a frame to a router while the packet targets the remote IP.
  • The switch is not automatically a gateway. The offline lab has no configured default gateway.
Slide 1019:00-23:00

IPv6: the same job, more space

  • The 2001:db8:: example is reserved for documentation. Show hexadecimal groups and compressed zeros briefly.
  • IPv6 link-local addresses use fe80::/10. Neighbor Discovery uses ICMPv6 for functions including neighbor and router discovery.
  • IPv6 is not automatic encryption. Do not promise that the travel router or any upstream supports global IPv6.
Slide 1123:00-25:00

Demo 1: no internet required

  • Show the real cables before opening terminals. Use the isolated lab, never the campus network.
  • Confirm both hosts, same VLAN, static addressing, and scoped ICMP firewall permissions in rehearsal. Windows command examples follow.
Slide 1225:00-29:00

Generate traffic. Read the tables.

  • Generate traffic from B as well if needed. Point out the Ethernet interface, address, prefix/mask, and physical address.
  • The switch learns source addresses from incoming frames. A known destination selects an egress port; an unknown one is flooded to eligible other VLAN ports.
  • Entries may already exist. Do not clear the whole MAC table for the presentation. Ping uses ICMP, not TCP.
  • If anything fails, spend at most 60 seconds, then use screenshots or text output saved from rehearsal. Do not fabricate output.
Slide 1329:00-32:00

One port can lead to many hosts

  • Disconnect B from the Catalyst first, then connect B to the unmanaged switch and add one uplink.
  • Wait for forwarding, ping, and inspect the MAC table. The source entry should move to the uplink after traffic arrives.
  • Never add a parallel cable to improvise a bundle. Unknown spanning-tree behavior is not a safe loop-prevention plan.
Slide 1432:00-35:00

Unplug it. What changes?

  • Unplug B, not the presenter’s console or display connection. Link negotiation and spanning tree can delay recovery.
  • Timeouts or unreachable messages vary with the host and state. Avoid promising exact output.
  • Tie the link failure back to OSI layer 1, then return to the slides at minute 35.
Slide 1535:00-38:00

TCP and UDP

  • IP itself does not guarantee delivery. TCP manages a stream above it, not message boundaries.
  • Do not describe UDP as simply bad TCP. Datagrams and application-controlled behavior are useful in their own right.
Slide 1638:00-41:00

How did the laptop get configured?

  • Use an ordinary browser request to connect names, addresses, and transport endpoints.
  • DNS is not limited to UDP. IPv6 configuration differs: router advertisements are important and DHCPv6 is not the IPv6 default-router mechanism.
  • The Catalyst and unmanaged switch need not provide DHCP for local Ethernet switching to work.
Slide 1741:00-44:00

DSL and cable

  • Do not attach universal speed numbers to these technologies. Actual service depends on equipment, deployment, plan, and conditions.
  • The modem handles access signaling; routing is a separate function even when one box combines both.
Slide 1844:00-47:00

Fiber and cellular

  • Fiber is not always dedicated or symmetric. Cellular is not the same link as Wi-Fi. The hotspot path on this slide is a conceptual example; the GL.iNet travel router is not assumed to contain a cellular modem.
  • Compare medium, mobility, deployment constraints, latency, and upload needs verbally. Avoid ranking technologies from one speed test.
Slide 1947:00-48:00

The whole path sets the limit

  • The presenter confirmed all 48 Catalyst copper ports are 10/100 Fast Ethernet. The link from the TP-Link therefore supports at most 100 Mb/s, even though the TP-Link supports Gigabit. Check show interfaces status for the actual negotiated speed and duplex. The four SFP slots remain unused without modules.
  • Other traffic, protocol overhead, host performance, and radio conditions can reduce throughput further.
Slide 2048:00-53:00

Demo 2: inspect the travel router

  • Finish the wired demo, disconnect the demo host from wired Ethernet, and join the GL.iNet Wi-Fi with automatic addressing. Rehearse router mode and local DHCP beforehand; keep the switch lab separate.
  • Inspect the actual DHCP server, assigned address, gateway, DNS settings, and route. Use observed values rather than a factory-default subnet. Router mode enables routing, DHCP, NAT, and firewall functions; access-point mode has a different role.
  • No upstream is needed to demonstrate local DHCP and the default route. A configured gateway does not prove internet access or demonstrate packet forwarding between networks. Only show a webpage if upstream access was separately rehearsed.
  • A rehearsed port-security demo or prepared Packet Tracer ARP/ping walkthrough may replace this five-minute slot. The earlier mobile hotspot is optional upstream hardware, not assumed part of this demo.
Slide 2153:00-56:00

Local ping works. A website does not.

  • Ask for a hypothesis and a check, not just a command. Local ping narrows the issue without identifying the cause.
  • Invite beginners to name a layer and experienced attendees to name a route, resolver, or service test.
Slide 2256:00-57:00

Troubleshoot one part at a time

  • Firewalls and policy can block ICMP while allowing an application. Conversely, a ping reply does not prove HTTP works.
  • There is no universal answer order for every outage. This is a useful starting process for the example.
Slide 2357:00-60:00

Questions

  • Protect the question slot. Optional appendix slides are available for questions, not extra required lecture time.
  • Afterward restore host addressing, Wi-Fi/VPN, scoped firewall rules, and original switch port settings. Verify restoration.
Slide 24Optional · replaces demo 2

Port security

  • This replaces minutes 48-53 only after rehearsal. Use console access and an unused host-facing lab port, not the uplink or an EtherChannel member.
  • Record the original configuration and enter the actual interface configuration context before these commands. Generate A traffic to learn its source, then swap in B before the secure address ages out.
  • Inspect show port-security interface with the actual interface name. Restrict should leave the port up while dropping unauthorized source traffic and recording violations.
  • For a previously unsecured port, no switchport port-security disables the feature. Restore the full original port configuration, verify ordinary traffic, and do not save temporary demo settings. See demos/README.md for setup and rollback.
Slide 25Optional · discussion only

EtherChannel

  • Two 100 Mb/s members do not normally make one flow run at 200 Mb/s. Hashing and platform capabilities determine distribution.
  • The TP-Link and GL.iNet are not confirmed compatible aggregation peers. Use a prepared Packet Tracer topology with two compatible switches for an optional simulation, or keep this conceptual. Do not add parallel cables to the physical lab.
